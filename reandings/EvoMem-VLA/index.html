EvoMem-VLA: State-Evolution Memory for Long-Horizon Robot Manipulation

这篇工作的核心是把“过去看到了什么”与“过去发生了什么变化”一起交给策略。它通过有方向、以源状态为条件的 delta tokens 保存交互变化，再以近期状态链和关键帧变化记忆支持动作生成。对 JEPA + VLA + Memory 方向，最值得关注的是变化表示是否保留任务进度，以及如何用受控消融区分变化编码与子任务规划的贡献。

1.What？

EvoMem-VLA 是一个面向长时程、依赖历史证据的机器人操作框架。官方 README 说明策略基于 StarVLA 的 QwenOFT 框架实现，视觉变化分支使用冻结的 DINOv3 特征。

它把记忆的基本内容从孤立的历史状态扩展为与状态证据绑定的变化表示。策略既能访问历史图像所描述的状态，也能读取有序帧对之间的 delta tokens，利用这些信息判断交互是否完成、当前处于哪个阶段，以及接下来应执行什么动作。

这里的 delta 表示来自两个已经观测到的状态。当前公开内容没有将它定义为未来预测误差、显式三维位移、光流或动作标签，也没有说明部署时通过梯度更新网络权重。

组件 公开资料确认的作用 需要避免的误读
Conditional Delta Tokenizer 编码有序 source–target 帧对，生成有方向、以源状态为条件的变化表示 直接做两帧特征相减
State-Evolution Memory 关联保存视觉状态与变化证据 只存一个递归向量或只有历史截图
Shared VLM 结合指令、当前观测、历史记忆支持多种输出 三个完全独立的主干模型
Task-adaptive routing 普通任务直接生成动作，多阶段任务先生成可执行子任务 每次动作都必须先输出自然语言推理

2.Why？

2.1 当前画面可以相同，正确动作却不同

重复举杯后，杯子回到相似位置；按钮按下再弹起后，图像也接近原状态。如果任务要求“先按左键九次，再按中键一次，最后按终止键”，当前图像无法单独确定还剩几次。控制需要追踪已经完成的交互。

历史截图能恢复部分证据，但稀疏抽帧仍会遗漏两个状态之间发生的过程。EvoMem-VLA 的出发点是：把变化作为明确的表示交给策略，降低策略从孤立状态中重新推断进度的负担。

2.2 为什么状态与变化要一起保存？

相同外观变化在不同源状态、不同物体或不同任务阶段下，含义并不相同。仅保存一个无上下文差值，难以说明“谁从什么状态变成了什么状态”。项目将 delta token 与对应状态证据配对，强调 source-conditioned 的方向关系。

这为对象状态与任务进度建模提供了入口，但不等于已经得到因果模型。公开模块输入描述是有序图像对，尚不能据此断言它分离了机器人动作、外部扰动和相机运动的影响。

3.How？

3.1 条件变化编码：冻结视觉表征，学习表示变化

方法图右上角给出了清楚的数据流：Source 与 Target 图像分别经过冻结的 DINOv3，输出特征送入 Delta Encoder，得到带有方向下标的 delta token。项目正文进一步说明它是 directional、source-conditioned 的编码。

**公开信息能确认的是输入、方向与用途。**Delta Encoder 的网络层数、token 数量、预训练数据、监督目标、是否使用重建解码器及其损失系数尚未公开。不能因为模块叫 tokenizer，就直接把它等同于带离散码本的 VQ 模型。

方法消融中的 naive feature difference 与学习型 delta tokenizer 有明确性能差距，说明在这个系统及协议下，简单特征差并未替代学习型编码。但这项消融本身尚未识别 tokenizer 究竟学到了动作结果、时间间隔还是其他辅助线索。

3.2 多尺度记忆：近期状态链与较早关键变化

方法图将历史分为两个部分：

  1. **Recent state-change chain：**初始观测、近期观测和当前观测之间插入三组 delta tokens。图中标注了初始时刻、当前时刻以及相隔 15、30 步的历史位置；这些下标不能在缺少采样协议时换算成秒或控制频率。
  2. **Keyframe-change memory：**保存更早的关键帧，并关联关键帧附近的变化证据。图中呈现关键帧与其前 15 步观测之间的 delta，形成较长期的状态—变化绑定。

官方 README 对使用范围有进一步限定：**RMBench 使用初始与近期观测及三组近期 delta tokens，不使用 keyframe memory；RoboMME 与真机任务启用 keyframe-change memory。**因此不能将 RMBench 的提升直接归因于长期关键帧模块。

图中虽然有 Keyframe Head，公开资料尚未给出它的标签构造、选择阈值、容量上限、替换规则或长期存储开销。多尺度表示不自动意味着固定容量或任意长历史均可保存。

3.3 共享 VLM 与任务路由

共享 VLM 接收当前观测、指令和状态演化记忆。方法图还显示 Prior Subtask History，并连接 Action Head、Subtask Head 和 Keyframe Head。

对于普通长时程任务，系统沿直接动作路径生成 action chunk；对于需要多阶段规划的任务，先生成可执行 subtask，再把它作为动作生成的附加条件。子任务在这里是控制的中间条件，而不是已经验证正确的环境事实。

“共享”与“分任务训练”的关系需要说清：项目说明每个仿真 benchmark 联合训练一个策略；真机按 embodiment 各训练一个策略。因此，它没有展示一个统一权重同时覆盖两个仿真 benchmark 和两种真机平台的结果。

3.4 对 JEPA 研究，变化编码和未来预测分别回答什么？

Delta Tokenizer 回答“这对已观测状态之间发生了什么变化”；动作条件世界模型回答“执行给定动作后，未来会怎样变化”。两者可以组成训练接口，但其学习信号不能混为一谈。

若后续用 JEPA 训练变化表示，必须额外检查：表示能否区分交互完成与失败，能否对视角和背景变化保持稳定，以及它是否改善历史不可见后的决策。这些是下面提出的研究实验，并非项目已经完成的验证。

4.实验结果

4.1 总体结果与比较范围

设置 EvoMem-VLA 成功率 项目列出的此前最佳比较值 差值
RMBench，9 个双臂操作任务 80.7% 67.8% +12.9 个百分点
RoboMME，16 个记忆任务 82.0% 44.5% +37.5 个百分点
真机，4 任务 × 2 平台 83.8% πMEM：30.0% +53.8 个百分点

“此前最佳”限定为项目比较的方法，不能外推为所有已发表方法的最新排名。特别是这里没有公开列出 T²Mem 等工作的同协议比较，不能把不同文章的 RoboMME 总分拼成严格排行榜。网页也未提供完整仿真评估次数、训练预算、多随机种子方差和逐任务结果。

4.2 消融：变化表示与子任务条件各贡献多少？

项目报告以下 RMBench 受控消融，说明各版本使用相同训练与评估协议：

版本 M(1) M(n) Overall
EvoMem-VLA 84.0% 76.5% 80.7%
换成朴素特征差 52.0% 41.0% 47.1%
移除 subtask route 84.0% 33.0% 61.3%
移除 delta tokens 59.0% 44.0% 52.3%
同时移除 delta tokens 与 subtask route 55.0% 31.0% 44.3%

M(1) 表示只需一个任务相关过去观测，M(n) 表示需要多个过去观测；这一区分本身不等同于单阶段／多阶段标签。

完整系统移除 delta tokens 后，Overall 下降 28.4 个百分点；移除 subtask route 后下降 19.4 个百分点。后者在 M(1) 保持 84.0%，在 M(n) 从 76.5% 降至 33.0%，显示复杂历史任务受子任务条件影响更大。

这两种贡献不能简单相加：相对同时移除两者的 44.3%，只保留 delta tokens 的结果是 61.3%，只保留 subtask route 是 52.3%，两者都保留是 80.7%。数据支持二者共同作用，也提醒我们必须控制训练条件与任务分组，不能用一个总分把提升全部归给记忆。

4.3 真机：成功率与演示片段是不同证据

任务 依赖的历史信息 两平台平均成功率
Lift Cup 卡片要求的次数与已完成次数 85.0%
Cover Ducks 杯子下的鸭子身份与揭盖顺序 90.0%
Route Recall 人示范的 3–6 个盒子顺序，允许重复 75.0%
Put Back Cup 杯子移走之前所在的初始盒子 85.0%

平台是 Franka 单臂与 AgileX COBOT 双臂。每任务、每平台评估 10 个 episode，总计 80 次；四项均值为 83.75%，按一位小数报告为 83.8%。每任务跨两平台共 20 次，因此一个 episode 就对应该任务均值的 5 个百分点。

网页提供 20 个代表性的成功录像，并注明不同视角不同步。这些录像用于说明任务过程；成功率来自独立评估统计，不能从展示录像的成功比例重新估计，也不能把不同视角当作同步传感器轨迹进行分析。

4.4 公开证据尚未覆盖的内容

项目没有给出变化编码的训练目标、完整算力与延迟、记忆容量曲线、长于训练长度的任务结果或记忆替换干预。论文和实现开放后，应优先核对：delta token 是否真的需要时间方向、keyframe 模块的独立收益，以及背景／相机变化对编码的干扰。

5.Takeaways:

5.1 最有价值的贡献：把交互变化变成策略的显式证据

我更看重其问题组织方式：记忆不仅应恢复某个过去状态，还应保留“什么交互已经发生”。状态与变化绑定有助于描述计数、顺序和阶段进度，RMBench 的 delta 消融提供了直接支持。

但端点变化并不保证保留全部过程。如果一个物体被移动后又放回，两张端点图像可能几乎相同；若完整循环发生在采样间隔之内，单个帧对仍难以恢复次数。这是基于输入信息的分析，尚非项目报告的失败实验。

5.2 和已有记忆路线怎么区分？

工作 主要保存或建模的内容 读出服务于什么
T²Mem episode 内快速权重中的观测关联 VLA 动作生成
World-T³ 位姿与场景内容的参数化关联 视频世界模型重访
EvoMem-VLA 历史状态与已发生变化的 token 证据 动作与可执行子任务
Slot-JEPA 固定 slot 基底下的观测转移 动作条件未来 mask 预测与规划

因此后续工作不能只以“加入变化 token”为创新表述。更有区分度的问题是：动作相关变化怎样被识别、如何与对象身份绑定，以及什么时候旧状态应当被覆盖。

5.3 面向 JEPA + VLA + Memory 的实验设计

以下是研究建议，不是原项目结果：

  1. **先隔离变化编码。**固定 VLA、数据、历史帧、token 预算和训练步数，对比状态记忆、朴素特征差、学习型变化编码，以及加入动作条件 JEPA 目标的版本；先固定 subtask route，再测试与其组合。
  2. **分别测试三个信息问题。**交换帧对顺序检验方向；替换源帧检验状态绑定；遮掉任务关键变化而保留相机运动，检查表示是否依赖无关视觉差异。
  3. **检验循环和更新。**加入移动后复位、按键失败、他人移动物体、阶段回退等轨迹，区分“动作发出”“交互完成”和“当前状态已改变”。
  4. **做记忆干预。**清空、打乱或跨任务交换 delta tokens，并在状态帧保持一致时比较动作变化。仅有准确率提升，尚不足以说明策略确实读取了正确历史。
  5. **同时报告代价。**除成功率外，测计数误差、阶段切换误差、身份一致性、token 数、推理延迟与随任务时长增长的存储开销。

5.4 组会三分钟总结

EvoMem-VLA 研究长任务里“看起来一样但该做的动作不同”的问题。它用冻结 DINOv3 与学习型 Delta Encoder，把有序观测对编码成与状态绑定的变化 token；近期变化链与部分设置启用的关键帧变化记忆供共享 VLM 使用，多阶段任务再生成子任务条件。项目报告 RMBench 80.7%、RoboMME 82.0%、真机 83.8%。最直接证据是移除 delta tokens 后 RMBench 从 80.7% 降到 52.3%，朴素差分也只有 47.1%。对我的研究，其启发是把历史状态、已发生变化和下一步预测联系起来；需要补充的验证是变化是否保留对象身份和真实完成状态，以及循环、遮挡和外部干预下能否正确更新。当前只公开项目资料，论文训练细节与代码仍待核验。
