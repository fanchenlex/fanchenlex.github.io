EvoMem-VLA: State-Evolution Memory for Long-Horizon Robot Manipulation

这篇工作把历史状态与已观测变化绑定，用源条件化压缩得到的 delta tokens，为 VLA 提供计数、顺序和阶段进度的证据。读完原文后，最关键的判断是：变化编码器先以特征重建训练，策略学习时冻结；动作监督训练的是如何使用这套表示。对 JEPA + VLA + Memory 方向，下一步应验证动作相关预测能否改进变化压缩，并用记忆干预检查策略是否读取了正确历史。

1.What？

EvoMem-VLA 研究长时程操作中的历史依赖：当当前画面相似，但已完成次数、物体原始位置或任务阶段不同时，正确动作应当不同。它在历史视觉状态之外，显式保存有方向、以源状态为条件的变化 tokens，让子任务生成与动作生成都能使用同一份状态演化记忆。

实现基于 StarVLA 的 QwenOFT。仿真从 Qwen3-VL-4B-Instruct 初始化，每个 benchmark 联合训练一个策略；真机从 StarVLA/VLAct_Qwen3_Pretrain 初始化，每种机器人训练一个策略。这里的共享主干是单个策略内部的共享，不是一个统一权重覆盖所有 benchmark 和机器人。

动作出口是残差 MLP，含两个 residual blocks，隐藏宽度为 VLM 的两倍。给定 H 个 action-query tokens，选取对应隐状态并预测动作块，以归一化 L1 动作损失监督。不能把其他 VLA 的 diffusion 或 flow-matching action expert 直接套到本模型。

组成 保存或处理什么 部署时的作用
视觉状态 tokens 初始、近期、已选择关键帧中的可见证据 保留对象与场景上下文
Delta tokens 特定有序帧对的源条件化变化 为交互进度提供紧凑证据
Keyframe Head action horizon 中各偏移的记录概率 安排未来观测的实际采集
Subtask route 从记忆生成当前可执行子任务 作为第二次主干前向的附加条件

这是 token 与观测组成的显式记忆。推理更新的是近期缓存、关键帧库及启用的文本历史，不是通过测试时梯度更新记忆权重。

2.Why？

2.1 保存状态之后，策略仍要推断发生了什么

举杯后放回、按键后弹起、搬动物体后回到中间位置，都可能产生相似的当前画面。初始帧或关键帧能保留过去看见的内容，却未必直接表达已完成交互。稀疏状态之间的变化，需要策略在执行动作时重新解释。

作者将问题组织为：把变化与对应视觉状态一起保存，减轻策略从稀疏截图恢复进度的负担。变化 token 提供“这两次观察之间发生的差异”，视觉状态提供这段差异所依附的对象与场景。

2.2 为什么不是直接特征相减？

特征差可以显式呈现两帧的变化，但未经学习的差分仍包含大量与任务无关的变化。EvoMem-VLA 沿用 DeltaTok 的条件压缩：让解码器在已经知道源状态的条件下恢复目标特征，迫使单个 token 保存源状态无法解释的目标信息。

这是一种学习型变化表示，不能直接等同于因果状态、动作类别或纯粹的机器人交互结果。它的重建目标也可能保留光照、相机或背景变化；这些内容是否被排除，仍需额外实验。

3.How？

3.1 Conditional Delta Tokenization：源状态已知时，压缩目标中的新增信息

给定有序图像对 (Iu,Iv) ，冻结的 DINOv3 提取 patch 特征：

fu=ϕ(Iu),fv=ϕ(Iv).

带学习 query 的编码器将这一对特征压缩为一个 token：

zu→v=gΔ(fu,fv;qΔ).

解码器同时接收源特征和 token，重建目标：

f^v=hΔ(fu,zu→v).

原文定义的 LΔ 是在 patches 和特征维度上平均的 log-cosh 重建损失。源特征已经提供背景与状态信息，瓶颈 token 用于补充恢复目标所需的信息。因此，token 是 source-conditioned、directional 的特征压缩，不是把每个像素位移显式编码出来。

3.2 精确时间对：初始锚点不等于最早 delta 的源帧

视觉锚点保留时刻 0,t−30,t−15,t 。三个近期 delta groups 按从新到旧记为 dt(1),dt(2),dt(3) ，实际帧对是：

dt(1): (t−15,t),dt(2): (t−30,t−15),dt(3): (t−45,t−30).

每个相机流、每对帧各产生一个 token。**最早一组不是 (0,t−30) 。**Figure 2 的简图把初始视觉锚点画在记忆链左侧，实际 source 要以 §3.2 和 Appendix A.4 为准。仅用于 tokenizer source 的 t−45 图像不会因此作为额外 RGB 记忆项进入 VLM。

近期记忆按 token 拼接为：

Mtanc=[V0;dt(3);Vt−30;dt(2);Vt−15;dt(1);Vt].

delta 紧邻其 target state。负时间下标 clamp 到 0，episode 开始时复用初始帧。这些间隔是观测步数，论文没有提供足够信息将它们统一换算为秒。

3.3 Event-state bank：保存关键帧及其局部变化

关键帧库按时间保存 (κi,oκi) 。每个事件条目额外编码 (κi−δe,κi) ，其中 δe 是事件局部间隔，Appendix A.4 明确 RoboMME 使用 15 步；主视角 delta token die 与对应视觉状态一起加入记忆：

Mt=[Mtanc;(die;Vκi)i=1mt].

近期 delta 对各相机流分别计算；事件状态与事件局部变化使用主视角。这里编码的是每条记录附近已经观测到的变化，不是相邻两个远距离关键帧之间的完整过程，也没有重建未观测的中间状态。

设置 近期 delta groups Keyframe memory 容量
RMBench 3 关闭 不使用
RoboMME 3 启用 16 帧

RoboMME 的记录阈值是 0.55；容量满后删除最旧记录，保留最新的 K 项。视觉记忆和 prior subtask history 在 episode 间清空。视觉条目有容量上限，但原文未给文本历史单独的 token 上限，不能据此断言完整输入和总耗时始终严格恒定。

3.4 Keyframe Head 预测何时记录，真实观测到达后才写入

从动作 query 的隐状态预测未来各偏移的记录概率：

p^t=σ(kω(ZtA))∈[0,1]H.

系统在满足记录条件的偏移中选最高分，超过阈值才安排采集。 j 对应时刻 t+j ，只有执行到该时间、真正获得观测后，记录才提交入库。

因此，预测的是“哪个时刻值得记录”，不是提前获得未来图像。Appendix A.1 说明 RoboMME 使用 native subgoal boundaries 为 keyframe supervision 提供标签来源。

3.5 Task-adaptive routing：任务级固定配置与两次前向

路由由任务配置指定，不是模型在线判断任务难度的分类器：

仿真任务 路由
RMBench 五个 M(1) 任务 Direct route
RMBench 四个 M(n) 任务：Battery Try、Blocks Ranking Try、Cover Blocks、Press Button Subtask-conditioned route
RoboMME 全部 16 任务 Subtask-conditioned route

直接路由在状态变化记忆和指令条件下生成动作。子任务路由额外使用既往文本历史 Rt ，先生成当前文本，再追加到同一上下文做第二次主干前向：

Ct=[Mt;L;Eℓ(Rt)],s^t=Decodeθ(Ct), A^t=Πθ,ψ([Ct;Eℓ(s^t)]).

训练使用真实 subtask text，部署使用生成文本，存在 teacher-forcing 与真实 rollout 的分布差异。部署的 Rt 累积历史预测，跳过空输出和连续重复；它不是经过环境核验的完成记录。语言结束 token 只结束文本解码，不能直接解释成任务已完成。

3.6 两阶段训练：变化重建与策略监督分开优化

Stage 1 训练／适配 delta encoder 和 decoder，冻结 DINOv3；Stage 2 冻结变化编码，再优化策略：

L=Lact+λlangLlang+λkfLkf.

动作 L1 监督所有样本；语言交叉熵只作用于目标子任务 token，direct-route 样本不贡献语言损失；关键帧使用带正类权重的 BCE，没有有效标签时为零。各损失先按有效元素归一化。由于 tokenizer 已冻结， LΔ 不在 Stage 2 的联合损失内。

仿真训练每 benchmark 80,000 steps，8 GPU、global batch 32、seed 42；主干学习率 10−5 ，动作头 10−4 ，warmup 5,000 steps 后余弦衰减。语言权重 0.005；RoboMME keyframe BCE 正类权重 7、损失权重 1。80,000 steps 不包括仿真 tokenizer 的适配更新。

真机每任务每 embodiment 收集 50 条示范，总共 400 条；每平台 200 条。VLA 全参数微调 60,000 steps、global batch 32、峰值学习率 5×10−5 ，变化分支冻结。预测 30 步动作，执行前 16 步后重规划。仿真预测 horizon 分别是 RMBench 50、RoboMME 20；不能将真机的执行步数直接套到仿真。

4.实验结果

4.1 先说比较协议

EvoMem-VLA 每个仿真 benchmark 联合训练一个策略，每任务评估 100 episodes：RMBench 共 900 次，RoboMME 共 1,600 次。RoboMME 各任务包括 50 easy、25 medium、25 hard。

仿真基线来自已发表结果，作者未重新实现或统一重训。RoboMME 原报告的基线使用每任务 50 episodes，平均三个 seeds 与三个 checkpoints；EvoMem-VLA 使用每任务 100 次，附录训练设置给 seed 42。这不是所有方法在统一种子与评估预算下的重跑。

RMBench 分组与总分按任务数加权，EventVLA 的总分保留原文 67.8%，不由展示的四舍五入任务分数重新计算。RoboMME 选各 baseline 总体最佳非 oracle 变体，排除 ground-truth symbolic memory。结果支持作者协议中的比较，但不应把不同论文的数字扩展成严格统一排行榜。

4.6 原文仍未回答的问题

论文没有给出端到端闭环延迟、随时长增长的开销曲线、单独关键帧增益、多种子不确定性或系统性的记忆替换实验。tokenizer 适配的独立总训练步数也未在 Table 4 中报告。单 token 与有界图像库不能替代完整效率评估，子任务路由还需要额外主干前向。

5.Takeaways:

5.1 相比只看网页，原文带来的核心判断

  1. **压缩目标明确了。**delta 通过源条件目标特征重建学习，不是动作标签监督的事件码。
  2. **优化边界明确了。**策略阶段冻结 tokenizer，动作损失学习消费变化信息，没有直接塑造变化编码器。
  3. **时间含义明确了。**近期三组都是 15-step 局部帧对，初始视觉锚点单独保存；关键帧也绑定局部变化，不补全整个过去过程。
  4. **路由含义明确了。**是任务配置与监督路径的选择，子任务文本历史是模型的既往预测，不是被核验的完成状态。
  5. **比较边界明确了。**RMBench 消融是同框架控制，仿真主表是已发表分数比较，真机使用同批示范。

5.2 对 JEPA + VLA + Memory，最值得继续的问题

EvoMem-VLA 回答“过去两个已观测状态发生了什么变化”；Slot-JEPA 让历史状态—动作转移服务于未来预测；T²Mem 用动作监督训练记忆机制的读写。这些路线提示一个更具体的问题：能否让变化压缩优先保留动作相关、能预测后果的内容，并在旧状态过时后正确更新？

这比“给 VLA 再加一个记忆模块”更具研究区分度。EvoMem-VLA 的冻结压缩器给出清楚的比较起点，但不能直接声称 JEPA 预测监督一定优于条件重建。

5.3 建议的最小实验

以下属于研究设计，不是原文结论：

  1. **固定策略与历史。**在同一 VLA、同一帧对和任务上，对比无 delta、朴素差分、冻结条件重建 token，再加入动作条件预测 token；同时控制输出 token 数、训练预算并单列预训练成本。
  2. **分清监督作用。**比较冻结 tokenizer、动作梯度可进入 tokenizer、加入 JEPA 预测损失的版本，检查改善来自读出还是压缩内容变化。
  3. **检验真实完成。**构造动作发出但操作失败、外部人员改变物体、阶段回退等情况，判断 token 是否反映实际结果，文本历史是否放大错误。
  4. **检验信息遗漏。**构造采样间隔内移动又复位的完整循环。若 source 与 target 几乎相同，仅靠端点不能恢复未观测过程；需评估更密集观测或事件积分是否必要。
  5. **干预记忆。**替换 source、反转时间、交换跨轨迹 delta，保持视觉状态与语言条件不变，观察决策是否跟随正确证据。
  6. **分层报告结果。**分别测计数、顺序、身份绑定、任务成功率与阶段误差，再测语言前向、delta 编码、关键帧更新和总闭环耗时。

5.4 组会三分钟总结

EvoMem-VLA 将长任务记忆从历史状态扩展为状态与变化的绑定。冻结 DINOv3 提取两帧特征，DeltaTok 式 encoder 用一个 token 压缩源状态不能解释的目标信息，并用源条件 log-cosh 特征重建训练；策略学习时冻结这条变化分支。三个近期变化组与视觉锚点交错，部分设置再用有界关键帧库保留较早证据，配置好的子任务路径通过两次共享主干前向生成动作。结果是 RMBench 80.7%、RoboMME 82.0%、真机 83.8%；同框架去掉 delta 后 RMBench 降至 52.3%，朴素差分只有 47.1%。原文也明确了路由、关键帧记录与比较协议。对我的方向，重点是检验动作条件预测能否让压缩更关注真实交互完成，并通过错误记忆、失败动作和复位循环验证其使用机制。
