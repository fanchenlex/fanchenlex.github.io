SimpleMemVLA: A Simple but Effective Native-Video Memory for Vision-Language-Action Models

这篇文章提出了一种原生视频记忆 VLA：不增加 memory bank、压缩器或循环状态，而是保留采样后、带时间戳的视频历史，让视觉语言骨干在当前决策时自己读取相关证据，再通过当前子任务的上下文隐藏状态驱动标准 flow-matching action head。核心判断是：当现代 VLM 的上下文窗口已经可以容纳分钟级视频时，应该把“保留什么”的决定推迟到真正需要动作的时刻。

1.What？

SimpleMemVLA 面向长时域、部分可观测的机器人操控。当前图像可能相同，但由于几分钟前发生的事件不同，正确动作也不同：机器人要记住目标被放在哪里、哪个物体曾被遮挡、按钮已经按过几次。反应式策略

π(at∣ot,ℓ)

在这些任务上信息不充分，策略必须使用

ht=(o≤t,ℓ).

已有记忆方法可分为符号存储、外部检索、学习压缩和循环状态。它们共同面临 write-time commitment：历史在写入时就要决定保留什么，而未来查询还没有出现，相关帧可能漏检、细节可能被压缩，旧证据可能被循环更新覆盖。

论文的做法是把采样后的视频历史按骨干预训练的原生 video 格式输入，用帧顺序和明文时间戳保留时间结构，让 self-attention 在当前决策时选择证据。作者给出的量级是：60 秒历史约 5.6k tokens，而上下文窗口为 262k tokens，理论上可容纳约 45 分钟历史。因此无需先写入独立记忆表示。骨干生成当前子任务的一句话，动作头只接收该 span 的 token embedding、上下文 hidden states 和当前本体状态。

2.Why？

作者重新审视了记忆选择发生的时间。检索器要提前猜测未来会用哪些帧；压缩器可能丢掉以后才有用的像素细节；循环状态可能覆盖早期事件。问题往往不是当前帧看不懂，而是当前帧无法区分历史不同的状态。

现代 VLM 已经通过视频预训练学到帧顺序和时间戳的处理方式。把历史改成数据库条目、摘要或循环 token，可能破坏原生接口。因此文章提出的对照问题是：

给同一个 VLA 骨干完整、按原生视频格式组织的历史，让它在读时根据当前子任务选择证据，是否比增加专用记忆模块更可靠？

同时，完整历史必须满足实时控制。连续决策共享大部分历史，所以作者把共享前缀的 prefill 与动作执行重叠起来。

3.How？

3.1 整体架构

论文使用 Qwen3.5-4B 视觉语言骨干。过去的头部相机帧走原生 video channel，当前腕部相机帧作为图像输入，本体状态单独编码。骨干生成当前子任务文本，DiT 风格 flow-matching action head 根据子任务和本体状态生成 action chunk：

timestamped video history→fθ→sub-task span→vϕ→action chunk.

memory 是骨干对显式视频历史的 self-attention 读取能力，不是额外模块。

3.2 在读取时选择历史

设头部相机原始帧率为 fc ，视频采样率为 fv ，历史窗口为 Tw 秒， s=fc/fv 。决策 t 的历史为：

Vt=(ot−(K−1)sh,…,ot−sh,oth),K=Twfv.

视频处理器把相邻帧组织为 temporal patches，并给每个 patch 加明文时间戳。标准部署使用窗口相对时间戳；SWA 变体使用 episode-absolute timestamps，使缓存 token 在窗口滑动时不必重新编号。当前腕部帧无历史时间戳，走 image channel。 Tw 决定可访问时间范围， fv 平衡 token 预算和事件覆盖。

3.3 子任务是历史到动作的窄通道

生成的子任务为

gt=(gt,1,…,gt,m)∼fθ(⋅∣xt),

解码上限为 64 tokens。动作头的条件是

Ct=[e(gt,1)⊕h(gt,1),…,e(gt,m)⊕h(gt,m),ψ(q¯t)],

其中 e 是 token embedding， h 是上下文 hidden state， ψ(q¯t) 是归一化本体状态的单 token 编码。

对归一化动作块 A¯t 、噪声 ϵ 和 τ∈[0,1] ：

Aτ=(1−τ)A¯t+τϵ, Lact=Eτ,ϵ∥vϕ(Aτ,τ∣Ct)−(ϵ−A¯t)∥22.

子任务监督目标由离线 cloud LLM 根据示范轨迹生成，总目标为

L=λsubLsub+λactLact.

历史必须先被骨干读出并写入 h(gt) ，动作头不直接读取历史视觉 prompt。

3.4 Exact streaming inference

连续决策的窗口只多出新的 temporal patch。机器人执行当前 action chunk 时，模型对共享历史前缀做 prefill 并缓存 key-value；下一次决策只处理新 patch、当前腕部帧和指令，然后生成新的子任务与动作。它与完整重算产生相同子任务输出。

论文报告的 60 秒配置：

  • 完整重算决策延迟：1.02 s；
  • streaming 决策延迟：0.68 s；
  • 额外后台 prefill：0.11 s，可隐藏在动作执行期间；
  • 45 分钟、约 245k tokens 历史：完整重算 32.1 s，streaming 1.18 s。

SWA 变体只保留 softmax attention 最近 60 个历史单元，让 linear-attention 状态从 episode 开始累积；决策耗时为 0.92 s，cache 和每步计算量不再随 episode 增长，但 RMBench 总体成功率从 94.0% 降到 91.0%。

4.实验结果

4.1 评测设置

四个记忆 benchmark 是 RMBench、RoboMME、MIKASA-Robo、RoboMemArena；两个通用控制集是 LIBERO 和 LIBERO-Plus。RMBench 是 RoboTwin 2.0 上的双臂单记忆/多记忆任务；RoboMME 覆盖 Counting、Permanence、Reference、Imitation；MIKASA-Robo 测试遮挡与部分可观测；RoboMemArena 有 26 个长轨迹任务，平均超过 1000 个控制步并报告 TSR/CSR；LIBERO-Plus 包含 10,030 个扰动任务。

4.2 结果

SimpleMemVLA 在四个记忆 benchmark 上都达到论文报告的最高结果：

  • RMBench：单模型跨十个任务；九个有已发表基线的任务平均 94.0%，单记忆 91.6%，多记忆 97.0%。最强 specialist 为 83.0%。
  • RoboMME：平均 88.3%，高于 GroundSG reference 的 84.1%。
  • MIKASA-Robo：平均 74.0%，比最强先前 VLA 的 44.4% 高 29.6 个百分点。
  • RoboMemArena：TSR 63.6%，CSR 72.1%；Occlusion TSR 64.3%，Counting TSR 71.4%，增益集中在需要历史的类别。
  • LIBERO：平均 97.5%，与最强报告结果持平。
  • LIBERO-Plus：零样本平均 78.4%，高于最强记忆增强模型。

4.3 同骨干对照：优势来自接口

作者固定骨干、数据、子任务监督、动作头和优化器，只改变历史接口。在 RoboMME 上：

记忆接口 RoboMME AVG
SimpleMemVLA native context 88.3%
Retrieval 31.5%
Token compression 22.6%
Recurrent state 20.6%

GroundSG 使用 ground-truth VLM 输出也只有 84.1%。这表明主要限制来自写入时的信息承诺，而不只是感知错误。

4.4 历史干预：策略确实在读记忆

作者固定模型、指令、当前观测、机器人状态和部署路径，只修改历史视频：

  1. 删除 Cover-blocks 中记录遮挡位置的帧会选择错误 cover；删除 MIKASA-Robo 的颜色线索会抓取错误颜色；删除 PickXtimes 的一次完整 pick-and-place 事件，输出会从“第四次”变成“第三次。
  2. 删除无关历史时输出保持不变。
  3. 用另一条 rollout 的 cover、颜色或 PatternLock 起始动作替换历史时，当前策略会跟随替换后的证据。

这些编辑没有训练监督，也没有参数更新。作者称其为 emergent visual in-context learning，说明历史不仅被输入模型，而且会因果地改变动作输出。

4.5 消融

  • Cover-blocks 需要约 25 秒前的遮挡事件；窗口缩到 15 秒后证据离开窗口，任务失败。Press-button 随窗口缩短逐渐下降。
  • 打乱帧顺序会让两个任务失败。
  • 去掉时间戳对 Cover-blocks 影响较小，但显著损害 Press-button，说明计数需要时间尺。
  • 替换 token embeddings 仍大体保持行为；替换或清零 hidden states 会使任务失败，甚至把行为导向替换 hidden states 所编码的目标。
  • 复用前一次决策的 hidden states 会明显下降，而复用陈旧位置 id 不会；子任务 hidden states 必须每次根据新历史刷新。

5.Takeaways:

5.1 最值得借鉴的思想

这篇工作的核心不是单纯扩大上下文，而是把记忆选择从写入时移到读取时：

先保留任务可能需要的感知证据，再在当前决策已经明确时让模型选择相关历史。

具身任务未来需要的内容往往不是预先定义好的事件摘要，而是一个当前才出现的查询：物体在哪里、动作是否已发生、哪段示范与当前状态对应。读取时选择保留了原始感知细节、时间顺序和证据关系。

5.2 对记忆 VLA 的启发

  1. 在增加 memory bank、summary token 或 recurrent state 前，先测同一策略直接读取原生视频历史。
  2. 除成功率外，加入历史删除、历史替换、帧顺序打乱和时间戳消融，检查模型是否使用了指定证据。
  3. 把骨干视为历史读取器和状态抽象器，把 hidden states 视为动作专家的记忆接口。
  4. 记忆和效率一起设计：共享前缀 prefill 降低决策延迟，SWA 约束 cache 与后台计算。
  5. LIBERO/LIBERO-Plus 说明保留历史不必然损害通用反应式操控。

5.3 局限性&未来工作：

  • 结论建立在 Qwen3.5-4B、六个 benchmark 和三类重建接口上，其他骨干、相机布局和动作专家仍需验证。
  • native context 仍受 Tw 、采样率和上下文窗口限制；关键事件早于窗口时仍不可访问。
  • Exact streaming 的 cache、位置范围和后台 prefill 随 episode 增长；SWA 将成本有界化，但 RMBench 从 94.0% 降到 91.0%。
  • 方法依赖视频预训练能力；没有原生视频接口的 VLM 不能简单通过拼接帧复现。
  • 子任务监督由离线 cloud LLM 生成，监督质量会影响历史到动作的窄通道。
  • 论文验证了历史使用和视觉 in-context adaptation，却没有揭示骨干内部完整的世界状态或因果模型。后续可结合状态探针、对象级因果表示和跨平台真机迁移。

对我自己的研究来说，最需要保留的判断是：当上下文容量允许时，先把证据完整带到当前决策，再让策略在读时选择，可能是比提前摘要更稳健的记忆基线。
